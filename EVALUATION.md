# Evaluation and learner adapter

Implement `team.run_topic(topic, topic_id)` to return a dictionary with `topic_id`, `memo` (plain text including citations and footnotes), `total_tokens` (actual provider-reported sum or null if unavailable), `turns`, `rejections`, `mcp_calls`, and `status`. Record model, settings, errors, cost where available, and detailed traces separately. Do not fabricate token counts or mark an unfinished run successful. The evaluator calls this function once per seed topic.

The baseline makes one model call over the whole corpus. The team should use the same model and settings; record differences, including that the baseline has full corpus access while the team retrieves excerpts. The comparison measures the chosen architectures, not a controlled experiment isolating all factors. Real provider calls may cost money; use an approved endpoint and check access first. Re-running causes new model calls.

`evaluate.py` applies the same automatic length, citation presence and source-ID checks to both systems. It counts all words in the returned memo including its title and footnotes; apply the assignment's 250–350 word body rule manually if necessary. It cannot verify factual support, tone or claim-level citation completeness. The `rubric_pass` field is therefore null. Manually review both systems against the same rubric and annotate each `rubric_pass` as true or false, recording evidence and reviewer decisions. An execution error is not a successful completion and must be reported; decide and document consistently whether errors count as rubric failures.

Failure rate = failed topics / evaluated topics. Error amplification = multi-agent failure rate / single-agent failure rate. If the baseline failure rate is zero, the ratio is undefined (including 0/0); report both rates and counts instead of dividing by zero or declaring success. The ratio is a target, not guaranteed by the starter. Save original and reviewed results and document any manual edits.

The sample search uses literal token overlap and may return irrelevant passages or fewer than three snippets. Test and improve retrieval as part of the assignment. The supervisor turn and rejection caps, persistent scratchpad, resume, token counting and idempotent memory compaction are learner tasks; the starter does not implement them. Check assignment limits, evaluator expectations and the availability of the selected model with your course team.
